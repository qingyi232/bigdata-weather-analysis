## 快速开始

### 1. 启动系统

#### 方式一：使用脚本一键启动（Windows）

```bash
# 切换到 scripts 目录
cd scripts

# 一键启动所有服务
start_all.bat
```

#### 方式二：手动启动各个服务

**步骤 1: 启动 Kafka**
```bash
# Windows
cd scripts
start_kafka.bat

# Linux
cd /usr/local/kafka
bin/zookeeper-server-start.sh config/zookeeper.properties &
bin/kafka-server-start.sh config/server.properties &
```

**步骤 2: 启动后端服务**
```bash
# Windows
cd scripts
start_backend.bat

# Linux
cd backend/api
python app.py &

cd ../data_collection
python kafka_producer.py &
```

**步骤 3: 启动前端服务**
```bash
# Windows
cd scripts
start_frontend.bat

# Linux
cd frontend
npm run dev
```

### 2. 访问系统

打开浏览器访问: **http://localhost:5173**

**演示账号：**
- 用户名: `admin`
- 密码: `admin123`

## 功能介绍

### 1. 实时数据大屏

**功能:**
- 实时显示多个城市的天气数据
- 温度趋势图表
- 降水量分布柱状图

### 2. 实时天气查询

**路径:** `/realtime`

**功能:**
- 查询指定城市的实时天气
- 查看详细气象参数
  - 温度、湿度、气压
  - 风速、风向
  - 降水量、能见度
  - 云量、紫外线指数

**API 接口:**
```bash
GET /api/v1/weather/realtime?city=北京
```

**返回示例:**
```json
{
  "code": 200,
  "message": "获取成功",
  "data": [
    {
      "station_id": "qweather_101010100",
      "station_name": "北京",
      "observation_time": "2024-01-01T12:00:00",
      "temperature": 25.5,
      "humidity": 60,
      "pressure": 1013,
      "wind_speed": 3.5,
      "weather_text": "晴"
    }
  ]
}
```

### 3. 历史数据分析

**路径:** `/analysis`

**功能:**
- 温度趋势分析（按小时/天/月）
- 地区气候统计
- 极端天气事件检测
- 历史数据对比

**支持的分析类型:**

#### 3.1 温度趋势分析
```bash
GET /api/v1/analysis/temperature-trend
  ?station_id=qweather_101010100
  &start_date=2024-01-01
  &end_date=2024-01-31
  &group_by=day
```

**参数说明:**
- `station_id`: 站点ID
- `start_date`: 开始日期
- `end_date`: 结束日期
- `group_by`: 分组方式 (hour/day/month)

#### 3.2 地区气候统计
```bash
GET /api/v1/analysis/regional-statistics
  ?province=北京市
  &start_date=2024-01-01
  &end_date=2024-01-31
```

#### 3.3 极端天气检测
```bash
GET /api/v1/analysis/extreme-weather
  ?start_date=2024-01-01
  &end_date=2024-01-31
  &event_type=高温
```

**极端天气类型:**
- 高温（≥40°C）
- 低温（≤-20°C）
- 暴雨（≥50mm）
- 大风（≥20m/s）

### 4. 天气预测

**路径:** `/prediction`

**功能:**
- 使用 LSTM 深度学习模型预测未来天气
- 支持温度预测
- 支持降水预测
- 显示预测置信度

#### 4.1 温度预测

**API 接口:**
```bash
POST /api/v1/prediction/temperature
Content-Type: application/json

{
  "station_id": "qweather_101010100",
  "hours": 3
}
```

**返回示例:**
```json
{
  "code": 200,
  "message": "预测成功",
  "data": {
    "station_id": "qweather_101010100",
    "prediction_hours": 3,
    "predicted_temperature": 26.5,
    "confidence": 0.85,
    "model": "LSTM",
    "prediction_time": "2024-01-01T12:00:00"
  }
}
```

#### 4.2 降水预测

**API 接口:**
```bash
POST /api/v1/prediction/precipitation
Content-Type: application/json

{
  "station_id": "qweather_101010100",
  "hours": 3
}
```

**预测时长:**
- 最短: 1 小时
- 最长: 72 小时（3天）
- 推荐: 3-24 小时（准确率最高）

## 数据采集

### 1. 数据源配置

在 `backend/config/config.yaml` 中配置数据源 API Key:

```yaml
weather_data_sources:
  # 和风天气（主要数据源）
  qweather:
    api_key: "你的API密钥"
    
  # OpenWeatherMap（备用数据源）
  openweathermap:
    api_key: "你的API密钥"
```

### 2. 手动采集数据

```bash
cd backend
python data_collection/kafka_producer.py

# 选择 "1. 单次采集测试"
```

### 3. 自动采集服务

启动后，系统会自动：
- 每5分钟采集一次实时数据
- 自动发送到 Kafka 消息队列
- 存储到 MySQL 和 HDFS

### 4. 数据采集监控

查看采集日志：
```bash
# Windows
type backend\logs\kafka_producer_YYYY-MM-DD.log

# Linux
tail -f backend/logs/kafka_producer_YYYY-MM-DD.log
```

## 天气预测

### 1. 训练 LSTM 模型

```bash
cd backend
python ml_prediction/lstm_model.py
```

**训练参数:**
- 序列长度: 24小时
- 预测时长: 3小时
- 隐藏单元: 128
- 训练轮数: 100

**模型评估指标:**
- MAE (平均绝对误差)
- RMSE (均方根误差)
- R² (决定系数)
- 准确率（±2°C容忍）

### 2. 使用预测服务

通过 API 调用预测：
```bash
curl -X POST http://localhost:5000/api/v1/prediction/temperature \
  -H "Content-Type: application/json" \
  -H "Authorization: Bearer YOUR_TOKEN" \
  -d '{"station_id": "qweather_101010100", "hours": 3}'
```

## 常见问题

### Q1: 数据采集失败怎么办？

**检查步骤:**
1. 确认 API Key 配置正确
2. 检查网络连接
3. 查看日志文件
4. 验证 Kafka 服务运行

### Q2: 预测准确率低怎么办？

**改进方法:**
1. 增加训练数据量
2. 调整模型参数
3. 增加输入特征
4. 使用更长的序列长度

### Q3: 前端无法连接后端？

**解决方案:**
1. 检查后端服务是否启动
2. 确认端口未被占用
3. 检查防火墙设置
4. 查看浏览器控制台错误

### Q4: Spark 任务运行慢？

**优化建议:**
1. 增加 executor 内存
2. 调整并行度
3. 启用数据缓存
4. 减少数据 shuffle
