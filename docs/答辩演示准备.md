## 三、常见问题准备

### Q1: 数据从哪里来？是真实数据吗？

**回答：**
> "数据来自和风天气API，这是一个真实的商业气象数据平台。
> 我在系统中配置了API密钥，可以实时获取全国各地的气象数据。
> 同时也支持 OpenWeatherMap 等其他数据源作为备份。
> 系统会每5分钟采集一次数据，保证数据的时效性。"

---

### Q2: Spark 和 Flink 的区别是什么？

**回答：**
> "Spark 和 Flink 是两种大数据处理引擎：
> - **Spark** 主要用于批处理，处理历史数据分析，比如计算过去一个月的温度趋势
> - **Flink** 主要用于流处理，处理实时数据，比如实时监控温度变化、发送预警
> 
> 在本系统中：
> - Spark 负责每小时执行一次的历史数据分析任务
> - Flink 负责实时处理从 Kafka 接收的数据流
> 两者互补，满足不同的数据处理需求。"

---

### Q3: LSTM 模型的准确率如何？

**回答：**
> "模型的准确率根据评估指标：
> - MAE（平均绝对误差）：约 1.5°C
> - RMSE（均方根误差）：约 2.0°C
> - R²（决定系数）：0.85
> - 在 ±2°C 误差范围内的准确率：85%
>
> 准确率受多种因素影响：
> 1. 训练数据量：数据越多，准确率越高
> 2. 预测时长：预测3小时比预测24小时准确率更高
> 3. 天气稳定性：晴天比极端天气更容易预测
>
> 未来可以通过增加训练数据、优化模型结构来提高准确率。"

---

### Q4: HDFS 存储了什么数据？

**回答：**
> "HDFS 主要存储非结构化和大规模数据：
> 1. 原始采集数据（JSON 格式）
> 2. 历史数据备份
> 3. 卫星图像和雷达图像（预留）
> 4. 训练好的机器学习模型
>
> 而结构化数据（如站点信息、实时数据表）存储在 MySQL 中。
> 这种混合存储方式兼顾了性能和灵活性。"

---

### Q5: 系统能支持多少并发用户？

**回答：**
> "系统采用了多种优化措施：
> 1. API 使用了 JWT 认证和速率限制
> 2. 数据库使用了连接池
> 3. 前端使用了 CDN 加速
> 4. 可以使用 Redis 缓存热点数据
>
> 在当前配置下（单机部署），可以支持约 100 并发用户。
> 如果需要支持更多用户，可以：
> 1. 使用 Nginx 负载均衡
> 2. API 服务水平扩展
> 3. 数据库读写分离
> 4. 使用 Kubernetes 容器化部署"

---

### Q6: 开发过程中遇到的最大困难是什么？

**回答：**
> "最大的困难主要有两个：
> 
> 1. **大数据环境搭建**
>    - Hadoop、Spark、Flink 的配置比较复杂
>    - 特别是在 Windows 环境下需要额外配置
>    - 解决方案：阅读官方文档，参考社区方案，最终成功搭建
>
> 2. **LSTM 模型调优**
>    - 初始模型准确率只有 60%
>    - 通过调整超参数（序列长度、隐藏单元数、学习率）
>    - 增加训练数据量
>    - 最终将准确率提升到 85%
>
> 这些困难让我深入学习了大数据技术和机器学习，收获很大。"
